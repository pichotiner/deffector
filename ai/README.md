# ИИ-сервис

Сервис компьютерного зрения для прототипа: находит узлы в кадре, оценивает видимые
дефекты узла и определяет образец оборудования по изображению. Вызывается только
бэкендом. Контракт — [plan/README.md, раздел 5.4](../plan/README.md); пункты ТЗ — 4.2
и идентификация по изображению из 4.1.

После установки сервис **не обращается в интернет**: все модели лежат на диске,
загрузка из сети в библиотеках отключена.

## Быстрый старт

Нужны Python 3.12 (подойдёт 3.13: `numpy` 2.5 требует 3.12+) и, для настоящих моделей,
видеокарта NVIDIA с 12 ГБ памяти и драйвером 570 или новее. Если команда `python`
запускает другую версию, `install.py` в Windows сам найдёт 3.12/3.13 через `py`.
Все команды выполняются из корня репозитория и одинаковы в Windows и Linux.

**Режим заглушки** — без моделей и видеокарты, для разработки бэкенда:

```bash
python ai/install.py --stub
```

```bash
python ai/run.py --stub
```

**Полная установка** (стенд и ПК с видеокартой):

1. Установить [Ollama](https://ollama.com/download) (в Windows — обычный установщик).
2. Скачать библиотеки и модели — около 10 ГБ, интернет нужен только на этом шаге:

   ```bash
   python ai/install.py
   ```

   В начале установка проверяет, что Ollama установлена и на диске хватает места.
   В конце — что torch видит видеокарту: если нет, установка завершается ошибкой
   (проверка без видеокарты — `--cpu`). Удачная установка оставляет отметку
   `ai/.venv/installed.json`. Если установка прервалась — просто запустите её снова:
   готовое пропускается, неполное окружение создаётся заново.

3. Запустить:

   ```bash
   python ai/run.py
   ```

Сервис слушает `http://127.0.0.1:8001`. Готовность — `GET /health`: пока модели
загружаются, ответ с кодом 503 и `status: "loading"`; когда всё готово — код 200,
`status: "ok"` и `ready: true`. Стенд целиком запускается из корня: `python stand.py`.
`run.py` сам запускает Ollama, если она ещё не запущена, и сразу останавливается
с подсказкой, если полная установка не дошла до конца (нет torch, весов или отметки
`ai/.venv/installed.json`). На ПК, где сервис ставился до 13.11, 19:00, один раз повторите
`python ai/install.py` — со скачанными файлами это быстро.

Чтобы принимать запросы с другой машины сети: `python ai/run.py --host 0.0.0.0`.

Если Ollama перезапускали или закрывали, пока сервис работал, перезапустите и сервис
(`python stand.py`): он заново загрузит модель в видеопамять при старте. Иначе первый
анализ после перезапуска Ollama может не уложиться в 15 секунд и вернуть «рекомендуется проверка».

### Особенности Windows

- `install.py` ставит PyTorch 2.11.0 из каталога сборок с CUDA 12.8
  (`https://download.pytorch.org/whl/cu128`) — она нужна видеокартам RTX 50xx. Если
  установка закончилась ошибкой «torch не видит видеокарту», обновите драйвер NVIDIA и
  повторите; другой каталог сборок со страницы pytorch.org — `python ai/install.py
  --torch-index <адрес>` (уже стоящая сборка без CUDA при этом переустанавливается).
- Ollama ищется в `PATH` и в `%LOCALAPPDATA%\Programs\Ollama`. Модели Ollama хранит
  в `%USERPROFILE%\.ollama\models`.
- Веса детектора и модели идентификации лежат в `ai\weights` (в репозиторий не
  попадают). Папку можно перенести с другого ПК вместо скачивания.
- Если вместо `python` установлен запускатель `py` — используйте `py ai/install.py`.
- Если на диске C мало места: Ollama можно не устанавливать, а распаковать архив
  `ollama-windows-amd64.zip` со страницы выпусков Ollama на GitHub в любую папку на
  другом диске. Тогда добавьте эту папку в `PATH` пользователя и задайте переменную
  `OLLAMA_MODELS` — папку для моделей (6 ГБ). PyTorch ставится без кэша pip;
  для остальных библиотек кэш выключается переменной `PIP_NO_CACHE_DIR=1`.

Проверено 13.11 на ПК Тимофея (Windows 11, RTX 5070 12 ГБ, драйвер 610.88, Python 3.12):
`install.py` ставит torch 2.11.0+cu128, видеокарта находится; Ollama 0.40.16 работает
на CUDA; `python stand.py` поднимает сервис и бэкенд, `check_scenario.py` проходит
с настоящими моделями. Холодный старт сервиса — около 45 с (из них 42 с — загрузка
мультимодальной модели в видеопамять).

### Проверка работы без интернета

Отключить сеть (вынуть кабель провайдера), перезагрузить ПК, выполнить
`python ai/run.py`, дождаться `ready: true` в `/health` и прогнать тестовый набор
(см. «Проверка качества»). Проверено в изолированной от сети среде: детектор и модель
идентификации загружаются с диска и отвечают; для `/analyze` нужна только локальная Ollama.

## Модели

| Задача | Модель | Откуда | Где лежит | Размер |
|---|---|---|---|---|
| Узлы и рамки (`/detect`) | OWLv2 base, детектор с открытым словарём | Hugging Face, `google/owlv2-base-patch16-ensemble` | `ai/weights/owlv2` | 0,6 ГБ |
| Дефекты и объяснение (`/analyze`) | Qwen2.5-VL 7B через Ollama | `ollama pull qwen2.5vl:7b` | хранилище Ollama | 6,0 ГБ |
| Идентификация (`/identify`) | CLIP ViT-B/32 (LAION-2B) | Hugging Face, `laion/CLIP-ViT-B-32-laion2B-s34B-b79K` | `ai/weights/clip` | 0,6 ГБ |

Все модели предобученные, общего назначения; на промышленных данных не дообучались.

**Почему OWLv2, а не YOLOE / YOLO-World.** На тестовых фото сравнили YOLOE (26l, 11l,
v8l), Grounding DINO tiny и OWLv2 base с одними и теми же названиями классов. YOLOE
давал оценки 0,05–0,2 и путал типы (задвижку называл насосом, фланец — манометром);
Grounding DINO склеивал названия классов. OWLv2 верно выделил двигатели, манометры
и арматуру на общих видах, поэтому выбран он. Он тяжелее YOLO, но на видеокарте
укладывается с большим запасом: 41 мс на кадр 640 пикселей (замер ниже).

**Видеопамять** (замер 13.11, RTX 5070 12 ГБ): Qwen2.5-VL 7B в Ollama — 5,4 ГБ
(с окном 4096), OWLv2 в половинной точности, CLIP и среда torch — около 2,4 ГБ.
Всего сервис занимает **7,8 ГБ**; вместе с рабочим столом Windows на карте занято
8,8–8,9 ГБ из 12 ГБ, пик во время `/analyze` — 8,9 ГБ. Фактическое значение
показывает `/health` (`gpu.memory_used_mb` — вся занятая память карты по `nvidia-smi`,
включая Ollama и другие программы). Если не помещается — уменьшить окно модели:
`AI_VLM_NUM_CTX=2048`.

## Запросы

Все запросы — `multipart/form-data`, поле `image` (JPEG или PNG). Ответы — JSON в UTF-8.
Ошибка: `{"error": {"code": "...", "message": "..."}}`; коды: `bad_image` (422),
`bad_request` (422), `model_loading` и `model_unavailable` (503), `internal_error` (500).

### `GET /health`

```json
{
  "status": "ok", "ready": true, "stub": false, "device": "cuda:0",
  "models": {
    "detector": {"name": "owlv2", "ready": true, "error": null, "load_seconds": 6.7},
    "vlm": {"name": "qwen2.5vl:7b", "ready": true, "error": null, "load_seconds": 21.0},
    "identifier": {"name": "clip", "ready": true, "error": null, "load_seconds": 2.0}
  },
  "classes": ["electric_motor", "pressure_gauge", "valve", "flange"],
  "reference_photos": {"PU-001": 4, "PU-002": 3},
  "gpu": {"name": "…", "memory_total_mb": 12282, "memory_used_mb": 9100}
}
```

Если одна модель не загрузилась, остальные запросы работают: `status: "degraded"`, код 200,
причина — в поле `error`. Если не загрузилась ни одна (например, нет torch) —
`status: "failed"` и код 503, чтобы стенд не счёл сервис готовым.
`gpu.memory_used_mb` берётся у `nvidia-smi` в фоновом потоке (раз в 5 секунд): в Windows
torch видит только свою память и не учитывает Ollama.

### `POST /detect` — распознавание узлов

Поля: `image`; `classes` — типы узлов из карточки. `classes` можно передать повторяющимся
полем, строкой через запятую (`valve,flange`) или JSON-списком. Без `classes` ищутся все
типы словаря; неизвестные типы пропускаются.

```json
[
  {"bbox": [0.41, 0.22, 0.12, 0.18], "cv_class": "pressure_gauge", "confidence": 0.87}
]
```

`bbox` — доли кадра `[x, y, ширина, высота]` от левого верхнего угла. `confidence` —
уверенность детектора, возвращается всегда. Список отсортирован по убыванию уверенности.
Сильно перекрывающиеся рамки подавляются, слишком большая рамка отбрасывается.
Это не гарантирует одну рамку на физический узел и верный тип предмета.

### `POST /analyze` — видимые дефекты узла

Поля: `image` (вырезанный узел), `component_type` (`type` из карточки), `component_name`.

```json
{
  "category": "check_recommended",
  "signs": ["коррозия"],
  "explanation": "На корпусе видны рыжие пятна, похожие на коррозию.",
  "recommendation": "Осмотреть корпус, оценить глубину коррозии.",
  "assessment_confidence": 0.7,
  "image_quality": "ok"
}
```

- `category` — строго `no_visible_issues`, `check_recommended` или `possible_defect`;
- `signs` — только из списка: `коррозия`, `течь/подтёки`, `механическое повреждение`,
  `следы перегрева` (последний — только для `electric_motor`, у других типов код его отбрасывает);
- `assessment_confidence` — оценка самой модели, **не калиброванная вероятность**;
- `image_quality` — `ok` или `poor`.

Что гарантирует код независимо от ответа модели:

| Ситуация | Результат |
|---|---|
| Снимок тёмный, смазанный или слишком мелкий (проверка кодом до модели) либо модель сама сочла снимок плохим | `image_quality: "poor"`, `check_recommended`, «По снимку оценить состояние узла нельзя» |
| Модель ответила `no_visible_issues`, но назвала признаки | `check_recommended` |
| Модель ответила `possible_defect` без признака из списка | `check_recommended` |
| В тексте есть «исправен», «в порядке», «дефектов нет», «в норме», диагноз, слова о внутреннем состоянии, назначение замены | текст заменяется шаблоном категории |
| Текст не на русском или длиннее двух предложений | шаблон / обрезка |
| Ответ не по схеме | один повтор |
| Второй сбой формата, превышение 15 секунд, Ollama недоступна во время запроса | `check_recommended`, «Автоматический анализ не выполнен.» |

Генерация почти повторяема (температура 0, фиксированное зерно), но не строго: на видеокарте
Ollama на одном и том же снимке иногда называет другой набор признаков. Категория в проверке
13.11 от этого не менялась.
Обязательные тексты-оговорки из контракта (раздел 5.1) добавляет бэкенд.

### `POST /identify` — идентификация по изображению

Поле: `image`. Кадр сравнивается с эталонными фото из `demo/reference/<equipment_id>/`.

```json
{
  "recognized": true,
  "candidates": [
    {"equipment_id": "PU-001", "confidence": 0.82},
    {"equipment_id": "PU-002", "confidence": 0.11}
  ]
}
```

Оценка образца — сходство кадра с ближайшим эталоном этого образца. `recognized: true`,
если лучшая оценка не ниже порога (`AI_IDENTIFY_THRESHOLD`, по умолчанию 0,66).
Какие эталоны лежат и как их подготовить к показу — [demo/reference/README.md](../demo/reference/README.md).
`confidence` — другая шкала, не сходство: доля образца среди кандидатов, умноженная на
близость к эталонам. Близость равна 0,5 ровно на пороге и 1 — на 0,15 выше него, поэтому
при сходстве ниже порога `confidence` всегда меньше 0,5 (бэкенд считает «распознано» по
`confidence ≥ 0,5`), а у постороннего предмета она близка к нулю у всех кандидатов. Эталоны читаются при
старте — после добавления фото сервис нужно перезапустить.

## Режим заглушки

`python ai/run.py --stub` (или `AI_STUB=1`). Модели не загружаются, ответы постоянные:

| Запрос | Ответ |
|---|---|
| `/detect` | двигатель, манометр, две задвижки (для проверки порядка слева направо) и фланец — как в карточке `PU-001`; фильтруется по `classes` |
| `/analyze`, `component_type=electric_motor` и любой другой | `no_visible_issues` |
| `/analyze`, `component_type=pressure_gauge` | `check_recommended`, признак «коррозия» |
| `/analyze`, `component_type=flange` | `possible_defect`, признак «течь/подтёки» |
| `/analyze`, `component_type=valve` | плохой снимок: `image_quality: "poor"`, `check_recommended` |
| `/identify` | `PU-001` — 0,82, `PU-002` — 0,11, `recognized: true` |

Примеры ответов `/detect` в заглушке:

```json
[
  {"bbox": [0.08, 0.30, 0.34, 0.42], "cv_class": "electric_motor", "confidence": 0.91},
  {"bbox": [0.41, 0.22, 0.12, 0.18], "cv_class": "pressure_gauge", "confidence": 0.87},
  {"bbox": [0.50, 0.40, 0.11, 0.20], "cv_class": "valve", "confidence": 0.78},
  {"bbox": [0.80, 0.42, 0.12, 0.21], "cv_class": "valve", "confidence": 0.72},
  {"bbox": [0.66, 0.52, 0.09, 0.16], "cv_class": "flange", "confidence": 0.66}
]
```

## Настройка

**Словарь типов узлов** — [classes.json](classes.json). Ключ — `cv_class`, он же `type`
узла в базе. Для каждого типа: английские названия для детектора (`prompts`, можно
несколько) и порог уверенности (`threshold`). Новый тип узла добавляется строкой
в этом файле, без изменения кода. Имена классов: `electric_motor`, `pressure_gauge`,
`valve`, `flange`.

**Переменные окружения** задаются в том же окне перед запуском (`python ai/run.py` или
`python stand.py`): в PowerShell — `$env:AI_IDENTIFY_THRESHOLD="0.7"`, в cmd —
`set AI_IDENTIFY_THRESHOLD=0.7`. Нечисловое значение останавливает сервис с понятной ошибкой.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `AI_STUB` | `0` | режим заглушки |
| `AI_HOST`, `AI_PORT` | `127.0.0.1`, `8001` | адрес сервиса |
| `AI_DEVICE` | `auto` | `cuda`, `cpu` или `auto` |
| `AI_WEIGHTS_DIR` | `ai/weights` | папка с весами |
| `AI_REFERENCE_DIR` | `demo/reference` | эталонные фото для идентификации |
| `AI_VLM_MODEL` | `qwen2.5vl:7b` | модель в Ollama |
| `AI_OLLAMA_URL` | `http://127.0.0.1:11434` | адрес Ollama |
| `AI_ANALYZE_TIMEOUT_S` | `15` | предел времени на `/analyze` |
| `AI_IDENTIFY_THRESHOLD` | `0.66` | порог распознавания образца |
| `AI_DETECTOR_MAX_AREA` | `0.85` | рамки больше этой доли кадра отбрасываются |
| `AI_MIN_BRIGHTNESS`, `AI_MIN_SHARPNESS`, `AI_MIN_SIDE_PX` | `30`, `15`, `64` | пороги проверки качества снимка |

## Проверка качества

Автотесты (модели не нужны):

```bash
ai\.venv\Scripts\python -m pip install -r ai/requirements-dev.txt
```

```bash
ai\.venv\Scripts\python -m pytest ai/tests
```

(в Linux вместо `ai\.venv\Scripts\python` — `ai/.venv/bin/python`).

Прогон тестового набора `demo/photos` через запущенный сервис — печатает таблицу ниже
и сохраняет фото с рамками:

```bash
ai\.venv\Scripts\python ai/tools/evaluate.py --draw eval_out
```

Разметка набора — `demo/photos/labels.json`: сколько узлов каждого типа на фото
и какие признаки ожидаются. Узлы считаются по количеству, положение рамок проверяется
глазами по картинкам из `--draw`.

### Результаты

**На видеокарте, 13.11, 18:30** — ПК Тимофея (RTX 5070 12 ГБ, Windows 11), весь набор:
41 фото с разметкой узлов (14 открытых, из них 2 посторонних, и 27 фото заказчика из `docs/case/`), анализ
дефектов — на 35 из них. Прогон: `ai\.venv\Scripts\python ai/tools/evaluate.py`.

| Что считаем | Результат |
|---|---|
| Узлов найдено из размеченных, по каждому типу | электродвигатель: 7 из 9; манометр: 3 из 4; арматура: 8 из 14; фланец: 5 из 11 |
| Рамок сверх размеченного количества узлов того же типа на кадр | 0,46 (19 на 41 фото; в основном на крупных планах — гайки и муфты приняты за фланцы) |
| Найден ожидаемый признак и назначена проверка или возможный дефект | коррозия: 20 из 20; течь/подтёки: 3 из 3; механическое повреждение: 4–5 из 5 (между прогонами); следы перегрева: 3 из 3 |
| Чистые кадры, получившие «видимых проблем не обнаружено» | 3 из 4 |
| Чистые кадры, ошибочно получившие «обнаружены признаки возможного дефекта» | 0 из 4 (один чистый манометр получил «рекомендуется проверка» с признаком «коррозия») |
| Кадры с дефектом, получившие «видимых проблем не обнаружено» | **0 из 31** |
| Время ответа `/detect` и `/analyze` | см. таблицу скорости ниже |

Скорость (через HTTP, как вызывает бэкенд; на карте одновременно загружены все три модели):

| Запрос | Медиана | 90 % запросов быстрее | Максимум |
|---|---|---|---|
| `/detect`, кадр 640 пикселей (205 запросов) | 41 мс — **23 ответа в секунду** (цель — 3–5) | 44 мс | 78 мс |
| `/detect`, фото исходного размера | 43 мс | — | 235 мс |
| `/identify`, кадр 640 пикселей | 7 мс | 10 мс | 14 мс |
| `/analyze`, вырезанный узел (43 запроса) | **1,6 с** (предел — 15 с) | 1,8 с | 1,9 с |

Замечания по прогону на видеокарте:

- на 11 из 31 кадра с дефектом модель назвала лишний признак сверх ожидаемого, чаще всего
  «механическое повреждение» (7 раз) — категория от этого не меняется, но список признаков
  бывает длиннее ожидаемого;

## ИИ: как работает, ограничения и риски

Раздел для презентации и сопроводительной документации.

**Как работает.** Три предобученные модели, каждая решает свою задачу. Детектор
с открытым словарём находит узлы по текстовым названиям типов — новый тип узла
добавляется строкой в настройках, без обучения. Мультимодальная модель смотрит на
снимок одного узла и отвечает строго по схеме: категория, признаки, объяснение,
рекомендация. Её ответ не показывается пользователю напрямую: код проверяет категорию,
разрешённые признаки и формулировки; при плохом качестве, техническом сбое или известных
противоречиях возвращает осторожный результат. Это не проверка истинности распознанного
типа и всех утверждений модели. Идентификация сравнивает кадр с эталонными фото образцов.

**Ограничения и риски:**

- анализ предварительный и только по видимым признакам;
- внутренние неисправности по изображению не определяются, система о них ничего не утверждает;
- «видимых проблем не обнаружено» не означает исправность — это прямо сказано в интерфейсе;
- ограниченный набор: четыре типа узлов и четыре признака (коррозия, течь/подтёки,
  механическое повреждение, следы перегрева — последний только у электродвигателя);
- результат зависит от освещения, ракурса и качества снимка; плохой снимок всегда даёт
  «рекомендуется проверка»;
- уверенность оценки дефекта — самооценка модели, она не калибрована;
- модели общего назначения, на промышленных данных не дообучались: возможны пропуски
  и ложные рамки, особенно на крупных планах с мелкими деталями; модель анализа
  склонна называть лишние признаки; ни один кадр с дефектом из 31 в данном прогоне
  не получил «видимых проблем не обнаружено», но это не гарантия вне набора и не
  означает, что все ожидаемые признаки найдены;
- при сбое или долгом ответе модели результат — «рекомендуется проверка», а не «проблем нет».

**Цифры проверки** (41 фото, из них 27 — фото заказчика; RTX 5070 12 ГБ):

- кадры с дефектом, получившие «видимых проблем не обнаружено», — 0 из 31;
- признак назван верно: коррозия 20 из 20, течь 3 из 3, механическое повреждение 4–5 из 5,
  следы перегрева 3 из 3; чистые кадры с категорией «обнаружены признаки возможного
  дефекта» — 0 из 4;
- рамки узлов — 23 раза в секунду (41 мс на кадр), анализ узла — 1,6 с,
  идентификация — 7 мс; видеопамять — 7,8 ГБ на все три модели;
- узлов найдено: двигатели 7 из 9, манометры 3 из 4, арматура 8 из 14, фланцы 5 из 11.

**Сильная сторона.** Всё работает локально, без интернета: снимки оборудования не
покидают сеть предприятия.

**Развитие.** Дообучение детектора на снимках конкретного оборудования, калибровка
уверенности на размеченных данных, расширение списка типов узлов и признаков.
