## 4. Основное исправление: анализ неверно выбранного узла — 45–60 минут с GPU

### Гипотеза

В `ai/app/analyzer.py` переданный тип сейчас задан как факт. Если попросить модель
сначала проверить соответствие объекта типу, она может перестать принимать ошибочную
рамку детектора за подтверждённый двигатель. Эффект нужно измерить: модель способна
ошибаться и в этой проверке.

- [x] Воспроизвести ошибку: подать снимок манометра с `component_type=electric_motor`.
      Сохранить текущий ответ. Проверить также арматуру, посторонний объект и правильные типы.
- [x] Проверить цепочку как в приложении: `/detect` → вырезать полученную рамку →
      JPEG → `/analyze` с типом ошибочной рамки. Отдельно сохранить ручной крупный план.
      Полный кадр и вырезанный узел учитывать раздельно: `evaluate.py` сейчас отправляет
      полное фото, поэтому один этот прогон не подтверждает исправление на телефоне.
- [x] Подготовить минимальное изменение внутренней инструкции и, если необходимо,
      внутренней JSON-схемы ответа модели. Публичный ответ `/analyze` не менять.
- [x] Разделить явное несоответствие, недостаток видимости и подтверждённое соответствие.
      Отсутствие внутреннего поля или сбой формата не считать подтверждением типа.
      При неопределённости использовать осторожный результат с причиной, а не
      произвольное утверждение о другом типе. Наличие нескольких объектов в кадре само
      по себе не означает несоответствие, если выбранный узел действительно различим.
- [x] При явном несоответствии возвращать `check_recommended` без приписывания дефектов
      выбранному узлу, с объяснением «Выбранный тип узла не подтверждён на снимке» и
      рекомендацией уточнить выбор или переснять. Сохранить действующие правила качества.
- [x] Проверку выполнять в том же запросе к VLM; измерить фактическую задержку.
- [x] Добавить регрессионные тесты обработки ответа: неверный тип, плохая видимость,
      отсутствующее/некорректное внутреннее поле, правильный тип с дефектом и без него.
      Проверить, что последующая обработка `rules.enforce` сохраняет объяснение
      несоответствия и пустой список признаков, а внутреннее поле не выходит в API.
- [x] Сравнить исходный и изменённый варианты на подготовленном наборе и полном наборе
      анализа из `demo/photos/labels.json`. Спорные ответы просмотреть по изображениям.
- [x] Для спорных кадров повторить оба варианта минимум трижды: на GPU ответ модели
      не строго повторяется даже при фиксированном зерне.
- [x] Между исходным и изменённым прогонами перезапустить ИИ-сервис: он не подхватывает
      правки автоматически. Не запускать два комплекта моделей одновременно для сравнения
      скорости и расхода памяти. Изменённый вариант должен измеряться в той же среде.

**Важно для оценки:** отказ анализировать неверно выбранный узел учитывать отдельно.
Он не означает обнаружение дефекта и не повышает полноту детектора.
