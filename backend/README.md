# Бэкенд

FastAPI + SQLite. Отдаёт телефону все 11 запросов контракта (раздел 5 [плана](../plan/README.md)),
хранит цифровые карточки, считает ресурс, сводит результаты ИИ с данными карточки,
записывает осмотры. Во внешнюю сеть не обращается.

ИИ-сервис Тимофея пока не подключён: `ai_mode` в `settings.json` равен `"stub"`, и ответы
на `detect`, `analyze` и `identify/image` приходят из заглушки (`app/ai_stub.py`). Всё
остальное — настоящее. Чтобы подключить ИИ-сервис, поставьте `"ai_mode": "real"` и его
адрес в `ai_url`. Точный формат обмена — [`docs/ai-contract.md`](../docs/ai-contract.md).

## Запуск (Windows и Linux одинаково)

Нужен Python 3.10 или новее.

```
python backend/run.py
```

При первом запуске скрипт создаёт `backend/.venv` и ставит зависимости — только в этот
раз нужен интернет. База `backend/data/deffector.sqlite3` создаётся и заполняется
демо-данными сама. В консоли будет адрес для телефона, например `http://192.168.1.20:8000`.

Параметры: `--port 8080` — другой порт, `--reload` — перезапуск при изменении кода.

**Сброс базы к исходным демо-данным** (перед каждым показом; бэкенд лучше остановить):

```
python backend/reset_db.py
```

**Проверка всего сценария одной командой** (контроль 2, после холодной перезагрузки без
интернета, утро перед защитой; бэкенд должен быть запущен):

```
python backend/check_scenario.py --image <снимок оборудования>.jpg
```

Проходит через бэкенд все 10 шагов сценария, как телефон, и пишет «ВСЁ РАБОТАЕТ» или
какие шаги не прошли. Заодно показывает, есть ли на ПК интернет. В конце сам сбрасывает
базу к демо-данным (`--no-reset` — не сбрасывать).

## Для Павла: подключение телефона

1. Телефон и ПК — в одной сети Wi-Fi.
2. Задать ПК постоянный адрес в роутере (резервирование DHCP).
3. Разрешить входящие подключения к порту 8000 в брандмауэре Windows: при первом
   запуске Windows спросит сама — поставить галочку «Частные сети». Если не спросила:
   «Брандмауэр Защитника Windows» → «Дополнительные параметры» → «Правила для входящих
   подключений» → создать правило для порта TCP 8000.
4. В браузере телефона открыть `http://<адрес ПК>:8000/api/health` — должен прийти
   `{"status":"ok", ...}`.

Страница `/docs` (Swagger) работает только при наличии интернета — на неё не рассчитываем.
Полное описание API без интернета — файл [`openapi.json`](openapi.json).

## Настройки — `settings.json`

| Ключ | По умолчанию | Что это |
|---|---|---|
| `ai_mode` | `"stub"` | `"stub"` — заглушка ИИ, `"real"` — ИИ-сервис по `ai_url` |
| `ai_url` | `http://127.0.0.1:8001` | адрес ИИ-сервиса |
| `ai_timeout_seconds` | 20 | `analyze` и `identify`: после этого — ошибка `503 ai_unavailable`, а не зависание |
| `ai_detect_timeout_seconds` | 3 | то же для `detect`: кадр не должен висеть |
| `resource_approaching_percent` | 80 | с какой выработки ресурс «приближается» |
| `maintenance_warning_days` | 30 | за сколько дней до обслуживания предупреждать |
| `identify_threshold` | 0.5 | ниже — `recognized: false`, приложение предлагает ручной выбор |
| `not_inspected_days` | 180 | узел без осмотра дольше — попадает в «требуют проверки» |
| `today` | `null` | зафиксировать дату, например `"2026-11-13"`; `null` — текущая |
| `db_path` | `data/deffector.sqlite3` | файл базы |

Любой ключ переопределяется переменной окружения `DEFFECTOR_<КЛЮЧ>`.

## Демо-данные

Два образца: `PU-001` насосный агрегат (QR `KST:PU-001`, S/N `SN2021-004587`) и `CC-001`
шкаф управления (QR `KST:CC-001`, S/N `SN2020-001233`). Файлы для печати — `demo/print/print.pdf`.

В данных заложены все случаи — каждая ветка срабатывает на показе. Полный список — в
начале `app/seed.py`. Для экрана самое заметное (`PU-001`):

| Узел | Ресурс | Визуальный анализ | Цвет рамки |
|---|---|---|---|
| N-02 электродвигатель | приближается: 92 % по наработке | признаки дефекта: коррозия | красный |
| C-02 манометр | обслуживание просрочено на 11 дней, давление выше уставки | рекомендуется проверка | красный |
| C-06 торцевое уплотнение | наступил срок замены (118 %) | не проводился | красный |
| C-03 задвижка всасывающая | приближается: 89 % по циклам | не проводился | жёлтый |
| N-01 насос | до обслуживания 19 дней | не проводился | жёлтый |
| C-04 задвижка напорная | в норме | видимых проблем нет | зелёный |
| C-05 фланец | недостаточно данных | не проводился | серый |

Даты подобраны так, что ни одно состояние не меняется до 16.11 (проверяется тестом).

## Уточнения контракта после этапа 1

Источник истины по формату — модели в `app/schemas.py` и выгруженный из них `openapi.json`:
FastAPI проверяет по ним каждый ответ. Что добавилось к разделу 5 плана и
`docs/meeting-stage0.md`:

| Где | Что |
|---|---|
| health | `{"status": "ok", "mode": "real", "ai": {"mode": "stub" \| "real", "status": "ok" \| "unavailable"}, "time"}` |
| карточка | `deviations_count` — число параметров с отклонением (для счётчика на вкладке) |
| компонент `visual` | `note` есть всегда: текст при `no_visible_issues`, иначе `null` |
| `resource.maintenance` | есть и `overdue_days`, и `days_left`; ненужное — `null` |
| `resource.missing_data` | коды: `installed_at`, `operating_hours`, `cycles`, `last_maintenance_at`, `normative`; по-русски то же перечислено в `basis` |
| detect | `candidates` есть всегда (`null`, кроме `ambiguous`); `label` у `matched` — название узла из карточки |
| attention | у каждого пункта `recommended_action` и `detectable` (найдёт ли узел ИИ); сюда же попадают узлы без осмотра дольше `not_inspected_days` |
| analyze | необязательное поле формы `detection_confidence` — уверенность рамки, по которой вырезан снимок |
| запись осмотра | `maintenance` без `component_id` — обслуживание оборудования в целом; для `maintenance` в `recommendation` — дата следующего обслуживания |
| ошибки | `503 ai_unavailable` — ИИ-сервис не ответил |

Все тексты для экрана (причины, рекомендации, подсказки, сообщения) бэкенд отдаёт готовыми —
приложение показывает их как есть.

## Решения этапа 2

- **Записанный дефект красит узел в красный.** Дефект, зафиксированный инженером (запрос 9,
  `type: defect`), — причина «Зафиксирован дефект: …» и уровень `defect`, пока по узлу не
  записано обслуживание или замена. Иначе после шага 10 узел оставался бы зелёным.
- **Карточку не кешируем в памяти.** План предлагал держать данные карточки в памяти ради
  скорости `detect`. Замер: бэкенд тратит на `detect` меньше 3 мс, ИИ — 100–300 мс; кеш
  ничего не ускорит, но после `reset_db.py` мог бы показывать устаревшие данные.
- **Ответ ИИ не по контракту не превращается в «проблем нет».** Неизвестная категория →
  «рекомендуется проверка», «Автоматический анализ не выполнен». ИИ не ответил → `503`,
  в базу ничего не записано.

## Тесты

```
cd backend
pip install -r requirements-dev.txt
python -m pytest
```

Тесты идут в GitHub Actions на Ubuntu и Windows при каждом пуше в `backend/`
(если в аккаунте GitHub доступны минуты Actions). `tests/test_ai_real.py` проверяет обмен
с ИИ-сервисом на поддельном сервере по `docs/ai-contract.md`.
После изменения моделей в `app/schemas.py` обновите схему: `python -m app.export_openapi`.

## Устройство

| Файл | Что делает |
|---|---|
| `app/main.py` | запросы API |
| `app/schemas.py` | контракт: модели всех ответов |
| `app/cards.py` | сборка карточек, правило `attention`, тексты для экрана |
| `app/resource.py` | расчёт ресурса (ТЗ 4.3) |
| `app/parameters.py` | сравнение параметров с уставками |
| `app/matching.py` | сопоставление рамок ИИ с узлами карточки |
| `app/lookup.py` | поиск по QR, номеру, маркировке |
| `app/ai_client.py`, `app/ai_stub.py` | обращение к ИИ-сервису и его заглушка |
| `app/db.py`, `app/repo.py` | схема SQLite и запросы к ней |
| `app/seed.py` | демо-данные |
| `check_scenario.py` | проверка всего сценария одной командой |
| `reset_db.py` | сброс базы к демо-данным |
