# Бэкенд

Сейчас это **заглушка**: все 11 запросов контракта (раздел 5 [плана](../plan/README.md))
отвечают в правильном формате, данные — демонстрационные, из `app/stub_data.py`.
Записи осмотров и результаты анализа хранятся в памяти и сбрасываются при перезапуске.
Ресурс в заглушке не пересчитывается. Настоящая база и расчёт появятся на этапах 1–2,
адреса и формат ответов при этом не меняются.

## Запуск (Windows и Linux одинаково)

Нужен Python 3.10 или новее.

```
python backend/run.py
```

При первом запуске скрипт создаёт `backend/.venv` и ставит зависимости — только в этот
раз нужен интернет. Дальше всё работает без сети. В консоли будет адрес для телефона,
например `http://192.168.1.20:8000`.

Параметры: `--port 8080` — другой порт, `--reload` — перезапуск при изменении кода.

## Для Павла: подключение телефона

1. Телефон и ПК — в одной сети Wi-Fi.
2. Задать ПК постоянный адрес в роутере (резервирование DHCP).
3. Разрешить входящие подключения к порту 8000 в брандмауэре Windows: при первом
   запуске Windows спросит сама — поставить галочку «Частные сети». Если не спросила:
   «Брандмауэр Защитника Windows» → «Дополнительные параметры» → «Правила для входящих
   подключений» → создать правило для порта TCP 8000.
4. В браузере телефона открыть `http://<адрес ПК>:8000/api/health` — должен прийти
   `{"status":"ok","mode":"stub",...}`.

Страница `/docs` (Swagger) работает только при наличии интернета — на неё не рассчитываем.

## Что умеет заглушка

| № | Запрос | Поведение |
|---|---|---|
| 1 | `GET /api/equipment?q=` | список двух образцов, поиск по названию, модели, номеру |
| 2 | `GET /api/equipment/lookup` | `qr=KST:PU-001`, `serial=SN2021-004587`, `marking=PU-001`; номера — без учёта регистра, пробелов, дефисов и путаницы O/0, I/1, S/5, B/8; иначе `suggestions` |
| 3 | `POST /api/identify/image` | всегда «Насосный агрегат» 82 % |
| 4 | `GET /api/equipment/{id}` | `PU-001`, `CC-001` |
| 5 | `GET /api/equipment/{id}/attention` | узлы `defect` и `check` с подсказкой «Наведите камеру на …» |
| 6 | `POST /api/equipment/{id}/detect` | фиксированные рамки, слегка покачиваются; для `PU-001` — `matched` и `ambiguous` (две задвижки), для `CC-001` — `matched` и `not_in_card` |
| 7 | `POST /api/equipment/{id}/components/{cid}/analyze` | всегда «Рекомендуется проверка», результат сохраняется |
| 8 | `GET /api/equipment/{id}/components/{cid}` | карточка узла |
| 9 | `POST /api/equipment/{id}/inspections` | запись в историю; дефект и замечание без комментария — ошибка 422 |
| 10 | `GET /api/equipment/{id}/history` | от новых к старым |
| 11 | `GET /api/health` | `{"status": "ok", "mode": "stub"}` |

В данных `PU-001` есть все цвета: `defect` (C-02, N-02), `check` (N-01, C-03),
`none` (C-04), `unknown` (C-05); все статусы ресурса и параметров.
