# Приёмка перед сдачей — 14.11.2026

**Решение: заморозить функции и модели.** Основной сценарий реализован, серверная
часть проходит тесты и работает с настоящим ИИ. Считать весь прототип окончательно
принятым пока нельзя: нужен финальный прогон на телефоне без внешней сети и фиксация
единой версии исходников, APK и стенда. Видео полного сценария и офлайн-проверки
в текущем комплекте отсутствуют.

Это итог аудита исходников и локальных проверок, а не подтверждение действий на
чужом ПК. Командные сообщения в этой сессии не использовались по просьбе пользователя.

### Отдельный пробел: уточнения Энже

[12 правил D1–D5 и V1–V7](tz/enzhe-2026-11-13.md) **не реализованы как полный набор
условий и действий**. Текущая система объединяет причины по ресурсу, отдельным уставкам
и визуальному анализу. Она не выполняет все требуемые в дополнении совместные проверки
трендов, токов, КПД, давления SCADA, чтение стрелки манометра, контроль кожуха и крепежа,
аудио и специальные 3D-указатели. Даже близкий по смыслу ресурс/ТО не доказывает D5
в точной формулировке с интервалами 4000/8000/16000 моточасов.

В общем плане обязательность дополнения оставлена на согласование; доказательства
согласованного сокращения в проверенных документах нет. **Если жюри требует все 12
правил, полного соответствия нет.** Перед сдачей нужно получить ясную границу объёма
от организаторов. Обещать реализацию всех правил или быстро имитировать её нельзя.

## Исправления при аудите

Изменения исправляют существующее поведение; схемы API, словарь типов, веса и пороги
моделей не менялись.

1. **AR выбирает правильный снимок.** Рамка хранит породивший её кадр; ответ уже
   выполнявшегося `detect` не подменяет кадр для анализа после нажатия.
2. **Замена не возвращает старый дефект.** Анализ привязан ко времени начала запроса;
   результат, начатый до замены, не восстанавливает состояние старого компонента.
   Новый анализ в ту же секунду не теряется. ISO-время может содержать дробные секунды.
3. **Сброс БД атомарен.** Ошибка наполнения демо-данными откатывает транзакцию.
4. **Стенд не маскирует ошибки.** Без `ai/run.py` нет автоматического перехода к
   заглушке; настоящий запуск перекрывает случайный `AI_STUB=1`; неуспех `--check`
   останавливает службы. `backend/run.py` передаёт код завершения Uvicorn.
5. **OpenAPI совпадает с зафиксированным JSON на Python 3.12.** Подпись HTTP 422 задана явно как в уже
   согласованном JSON; сам контракт не редактировался.
6. **Плохой снимок объясняется честно.** Свободный ответ модели не подменяет сообщение
   о невозможности оценки. Скрипт качества прекращает расчёт при HTTP-ошибке анализа
   или техническом отказе модели; подсчёт числа рамок не называется точностью координат.
7. **Материалы сдачи соответствуют фактам.** README и ответы не ссылаются на готовые
   отсутствующие ролики. PDF создаётся с отдельным профилем браузера, ожидает завершения
   печати и сохраняет прежний файл при неудаче.
8. **Сборка Android проходит из текущего Windows-пути.** Разрешён путь с кириллицей,
   убраны кавычки из PATH дочернего процесса и принудительная UTF-8 кодировка JVM,
   ломавшие запуск тестового процесса. Новый APK собран с тестами и Lint.

## Порядок оставшихся двух часов

Интервалы — от начала финальной приёмки, без привязки к уже прошедшим срокам планов.
Не тратить этот резерв на смену моделей, настройку новых порогов и новые сценарии.

| Интервал | Действие | Критерий завершения |
|---|---|---|
| 0–15 минут | Зафиксировать один кандидат исходников и собрать APK; сверить версию на ПК показа | Один SHA исходников, APK из этого состояния, рабочие веса заранее установлены |
| 15–45 минут | Холодный прогон без внешней сети с телефоном, одновременно записывать | QR → карточка → список внимания → рамки → анализ → ресурс → все виды записи → история; без загрузок извне |
| 45–65 минут | Проверить Э1, лист 6, при наличии времени лист 9; убрать неподтверждённые объекты | Предсказуемый сценарий при реальном свете, корректная область анализа; лист 9 последним |
| 65–85 минут | Сохранить короткое видео сценария и подтверждение автономности | Реальные файлы открываются на ПК ведущего; склейки/ускорение не скрывают сбои |
| 85–105 минут | Репетиция с видеозвонком и трансляцией | Читаемые карточки/причины, приемлемое время ответа, запас видеопамяти; запасное видео открыто |
| 105–120 минут | Сбросить демо-БД, сверить пакет и зафиксировать сдаваемую версию | Исходники, APK, PDF/HTML, README, QR/листы, видеозаписи; после этого только проверенные исправления |

Команды на **подготовленном ПК показа**, из корня проекта:

```text
python mobile/build.py --offline
python stand.py --reset --check --image demo/reference/PU-001/case_pump_01.jpg
```

После ручного прогона, перед показом: `python backend/reset_db.py`. Остановка служб —
`Ctrl+C` в окне стенда. При API-проверке смотреть весь вывод: существующий
`check_scenario.py` может завершаться успешно с предупреждениями о нераспознанном
изображении/отсутствии рамок; одна строка «ВСЁ РАБОТАЕТ» недостаточна.

Порядок показа — [speech.md](presentation/speech.md). Листы 4, 5, 8 не использовать;
манометр открыть из списка внимания, а не выдавать чужую рамку за его распознавание.
После чистого листа 9 двигатель может стать серым из-за отсутствия норматива — это
корректно. Исходный красный двигатель после сброса — сохранённый демо-осмотр.
