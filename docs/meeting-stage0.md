# Решения этапа 0 — 13.11

Встречу заменили этим документом. Решения приняты, контракт заморожен: дальше
изменения — только по согласию всех троих (правило 5 плана).

## 1. Рамки демо — утверждены

- Образцы оборудования: `PU-001` насосный агрегат (основной), `CC-001` шкаф управления.
- Распознаваемые типы узлов: `electric_motor`, `pressure_gauge`, `valve`, `flange`
  ([словарь](component-types.md)).
- Типы только для карточки (ИИ их не ищет): `pump`, `circuit_breaker`.
- Шкаф управления — второстепенный образец: в нём ИИ распознаёт только вентилятор
  (`electric_motor`). Отдельный тип для шкафа не добавляем — весь показ AR идёт на `PU-001`.
- Признаки дефектов: коррозия, течь/подтёки, механическое повреждение.
- Серийные номера и маркировка — латиницей и цифрами: `SN2021-004587` / `PU-001`,
  `SN2020-001233` / `CC-001`; QR — `KST:PU-001`, `KST:CC-001`.
- Показ: телефон наводим на распечатки или фото на втором мониторе; запасной вариант — видео.

Исключение: если Тимофей до 15:00 увидит, что детектор не находит какой-то тип узла
на наших фото, он сообщает — тип заменяем, словарь правит Андрей.

## 2. Контракт: раздел 5 плана + уточнения

Уточнения появились при написании заглушки и смысла контракта не меняют.
Эталон формата — ответы заглушки (`python backend/run.py`).

| Где | Что добавлено | Зачем |
|---|---|---|
| компонент | `order` — порядок слева направо (число или `null`) | различать однотипные узлы при сопоставлении |
| компонент `visual` | `note` — только при `no_visible_issues`: «Отсутствие видимых дефектов не подтверждает исправность оборудования» | обязательный текст ТЗ приходит готовым |
| `resource.maintenance` | `days_left` (если срок не наступил) рядом с `overdue_days`; при отсутствии интервала обслуживания — `maintenance: null` | текст «через N дней» |
| карточка оборудования | `normative` и `usage` — как у компонента | нормативный срок оборудования в целом (4.3) |
| `detect`, `ambiguous` и `not_in_card` | `component_id: null`, `attention_level: "unknown"`, `reason` с пояснением; у `ambiguous` — `candidates` | приложение рисует серую рамку с подписью |
| запрос 9, ответ | `{"inspection": {…запись истории…}, "component": {…} или null}`; код 201 | «созданная запись и обновлённый компонент» |
| запрос 9, ошибки | `422 comment_required` — дефект или замечание без текста; `maintenance` и `replacement` без `component_id` — `422 validation_error` | |
| запрос 1, ответ | `{"items": [{id, name, model, serial_number, marking, location}]}` | список для ручного выбора |
| запрос 11, ответ | `{"status": "ok", "mode": "stub" \| "real", "time": …}` | Павел видит, с чем работает |
| все ошибки | `{"error": {"code", "message"}}`; коды: `not_found`, `bad_request`, `validation_error`, `comment_required` | |
