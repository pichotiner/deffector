# Стенд на ПК Павла — инструкция

Для Павла: как поставить, запустить, остановить и проверить бэкенд и ИИ-сервис на своём
ПК (Windows). Всё — из корня репозитория, обычной командной строкой или PowerShell.
Чек-листы для проверки без интернета, утра защиты и пробного звонка — в конце.

Достаточная приёмка и актуальный остаток — [короткий план сдачи](../plan/acceptance.md).
Принятые проверки повторяем после затрагивающих их изменений или нового сбоя.

## Один раз: установка

1. Python 3.12 (подойдёт 3.13) с python.org, при установке — галочка «Add python.exe to PATH».
   Проверка: `python --version` (или `py -0` — список установленных версий). ИИ-сервису
   нужен именно 3.12–3.13; если `python` другой версии, `ai/install.py` сам найдёт 3.12 через `py`.
   Для ИИ-сервиса ещё: [Ollama](https://ollama.com/download) обычным установщиком и драйвер
   NVIDIA 570 или новее (`nvidia-smi`); на диске C — не меньше 15 ГБ. Первый запуск качает
   около 10 ГБ.
2. `git clone` репозитория (или `git pull` в `main`, если уже есть).
3. **Первый запуск — с интернетом:** `python stand.py`. Бэкенд создаст `backend/.venv` и
   поставит зависимости, ИИ-сервис — свои (подробности и веса моделей — `ai/README.md`).
   Дальше интернет не нужен. Если установка ИИ-сервиса оборвалась или ставилась только
   заглушка (`ai/install.py --stub`), стенд при следующем запуске сам доустановит: готовой
   считается только полная установка (отметка `ai/.venv/installed.json`).
4. Брандмауэр: при первом запуске Windows спросит про доступ Python к сети — поставить
   галочку **«Частные сети»** и разрешить. Если не спросила — `backend/README.md`, раздел
   «Подключение телефона».
5. Телефон и ПК — в одной локальной сети, домашняя сеть в Windows — «Частная».
   В приложении — текущий адрес ПК из окна стенда. Резервирование DHCP желательно,
   но достаточно сверить адрес после смены сети; проверена точка доступа телефона.

## Каждый раз

| Что | Команда |
|---|---|
| Запустить всё | `python stand.py` |
| Запустить перед показом | `python stand.py --reset --check --image demo/photos/<снимок>.jpg` |
| Остановить всё | `Ctrl+C` в окне стенда (или закрыть окно) |
| Сбросить базу к демо-данным | `python backend/reset_db.py` (или `--reset` при запуске); вход на телефоне сохраняется |
| Вернуть демо-учётные записи | `python backend/reset_db.py --users` — все входы завершаются |
| Проверить сценарий | `python backend/check_scenario.py --image demo/photos/<снимок>.jpg` |
| Только приложение, без ИИ | `python stand.py --stub` — рамки ненастоящие, **не для показа** |

Что делает `python stand.py`: запускает ИИ-сервис, ждёт, пока он загрузит модели (до 10
минут, пишет «ещё запускается»), запускает бэкенд и пишет:

```
СТЕНД ГОТОВ
  Адрес для телефона:  http://192.168.1.20:8000
  ИИ:                  настоящий, http://127.0.0.1:8001
```

В строке «ИИ» должно быть **«настоящий»**. «ЧАСТИЧНО» — загрузились не все модели (ниже
написано какая и почему), «ЗАГЛУШКА» — стенд запущен с `--stub`: с такими показывать нельзя.

Этот адрес — в настройки приложения. Затем вход в приложении: для показа — мастер,
`master@kst.local` / `Master-102` (осмотр и выгрузка отчётов); инженер —
`engineer@kst.local` / `Engineer-102`, администратор — `admin@kst.local` / `Admin-102`.
Вход действует 24 часа и переживает сброс базы. После обновления из `main` первый запуск
стенда один раз требует интернет: ставится библиотека для отчётов в PDF.
**Если на телефоне сборка без экрана входа** — в `backend/settings.json` поставить
`"auth_required": false` и перезапустить стенд: приложение работает как раньше, без отчётов.

Окно стенда не закрывать: в нём работают обе службы.
Если одна из них упадёт, стенд напишет какая, покажет конец её журнала и остановится —
запустите снова. Журналы: `logs/stand-ai.log`, `logs/stand-backend.log`.

`--check` после запуска проходит вход, все 10 шагов сценария и выгрузку отчёта через бэкенд и пишет
«ВСЁ РАБОТАЕТ» или что сломалось; потом сам сбрасывает базу. Если проверка завершилась
с ошибкой, стенд останавливается с ненулевым кодом. `--image` — снимок оборудования
с узлами: для API-проверки подходит `demo/reference/PU-001/case_pump_01.jpg`.
Этот исходник не заменяет проверку камеры телефона. Настоящий запуск принудительно
отключает `AI_STUB`; заглушка доступна только через явный `--stub`.

## Если что-то не так

| Что видно | Что делать |
|---|---|
| `Порт 8000 уже занят` | стенд уже запущен в другом окне — закрыть его, запустить снова |
| `ИИ: не ответил … за 600 с` или `ИИ: служба остановилась` | открыть `logs/stand-ai.log`, переслать конец Тимофею |
| `ИИ: не загрузилась ни одна модель — …` | стенд остановился сразу; причина — в этой же строке (нет torch, не видна видеокарта): повторить `python ai/install.py`, см. `ai/README.md` |
| `ИИ: [!!] ЧАСТИЧНО … не загружено: …` в «СТЕНД ГОТОВ» | названная модель не загрузилась (чаще всего не запущена Ollama) — исправить и перезапустить стенд |
| `бэкенд: служба остановилась` | открыть `logs/stand-backend.log`, переслать конец Андрею |
| `[!!] ИИ-сервис не отвечает на /health` во время работы | анализ на телефоне не пройдёт; `Ctrl+C` и `python stand.py` |
| Телефон не открывает `http://<адрес>:8000/api/health` | ПК и телефон в одном Wi-Fi? адрес тот, что в «СТЕНД ГОТОВ»? сеть Windows «Частная»? правило брандмауэра для порта 8000 |
| Телефон показывает ошибку `ai_unavailable` | ИИ-сервис не ответил вовремя: кадр пропускается сам; если при анализе — повторить |
| В карточках остались записи с прошлого прогона | `python backend/reset_db.py` |
| Адрес ПК поменялся | закрепить адрес в роутере; в приложении поправить адрес сервера |
