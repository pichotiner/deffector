# Материалы кейса

Папка проекта от заказчика (Яндекс.Диск «Кейс»), скопирована как есть 13.11.2026.
Здесь — что в ней и как мы это используем. Технического задания в папке нет: ТЗ —
[`docs/tz/`](../tz/).

14.11 убрана вторая папка `docs/case-materials/`: 80 файлов совпадали по SHA-256.
Один отличающийся XLSX сохранён в `Варианты исходников/БД значений (вибрация) — копия Тимофея.xlsx`.
Основной XLSX в `Вибрация/` не заменялся; извлечённые данные бэкенда не менялись.
Отличия внутри XLSX затрагивают XML листа, оформление и метаданные; равенство значений
ячеек не предполагается. Уникальная версия сохранена целиком.

## Как данные заказчика попали в прототип

- **Два образца — оба из материалов.** `PU-001` — центробежный агрегат Wilo CronoLine-IL
  65/160-5,5/2: под него сводный документ заказчика, а базы вибрации и температуры сняты
  при 2900 об/мин — двухполюсный центробежный насос; на фото кейса — такие же агрегаты.
  `PU-002` — винтовой агрегат AMS №1 из паспортов.
- **Нормативы — из документов.** Где документ говорит «по состоянию» (рабочее колесо,
  муфта, статор, ротор), норматива в карточке нет, и экран честно пишет «недостаточно
  данных». Регламент Wilo задан в моточасах (ТО-1 — 4000 ч, ТО-2 — 8000 ч): при
  круглосуточной работе это ≈ 167 и ≈ 333 суток.
- **Параметры — из баз значений.** Текущее показание — строка базы на момент настройки
  `telemetry_at` (по умолчанию 13.11.2026 09:00 — всё в норме). Уставки предупреждения и
  тревоги и диагнозы — из описаний баз. Автотест сверяет наш статус с диагнозом заказчика
  в каждой строке базы вибрации.
- **Что будет дальше по данным заказчика** — в самих базах: 15.11 13:00 начинается рост
  дисбаланса, 17.11 — тревога, затем расцентровка, износ подшипника, перегрев. Показать
  любой момент (на вопросы жюри):

  ```
  DEFFECTOR_TELEMETRY_AT="2026-11-17 02:00" python backend/reset_db.py
  ```

  после этого рабочее колесо красное: «Тревога: выше 4,5 мм/с … — высокий дисбаланс
  рабочего колеса». Вернуть — `python backend/reset_db.py`.
- **Чего в материалах нет и взято типовым:** задвижки, манометр, обвязка, фланец
  `PU-001` (нормативы — по типовым паспортным значениям), давление на выходе `PU-001`
  (единственный параметр-отклонение на 13.11 — чтобы показать сигнализацию).
- **Учёт эксплуатации — демонстрационные данные:** наработка, даты установки и замен,
  история осмотров, показания `PU-002`. Заказчик дал документацию и замеры, но не журналы
  эксплуатации. Организаторы разрешили моделировать недостающее, если это подписано:
  в карточке каждого образца на экране есть строка «Данные эксплуатации — демонстрационные
  данные…».
