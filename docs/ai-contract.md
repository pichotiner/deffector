# Контракт бэкенд ↔ ИИ-сервис — точный формат

Дополняет раздел 5.4 плана. Так бэкенд (`backend/app/ai_client.py`) обращается к ИИ-сервису
Тимофея. Всё по HTTP в локальной сети, по умолчанию `http://127.0.0.1:8001`
(настройка `ai_url` в `backend/settings.json`). Системные прокси бэкенд не использует.

Этот формат проверяется автотестами `backend/tests/test_ai_real.py` на поддельном
ИИ-сервисе: если ваш сервис отвечает так же, интеграция заработает сразу.

Картинки — `multipart/form-data`, поле `image`, JPEG. Остальные поля — обычные поля формы.

## `GET /health`

Любой ответ с кодом 200 — сервис готов. Пока модели грузятся, отвечайте 503.
Бэкенд ждёт ответа не больше 2 секунд.

## `POST /detect` — рамки узлов

Вход:

| Поле | Пример | Что это |
|---|---|---|
| `image` | JPEG, ширина ~640 | кадр с камеры |
| `classes` | `electric_motor,pressure_gauge,valve,flange` | **одна строка через запятую** — типы узлов из карточки |

В FastAPI: `image: UploadFile = File(...), classes: str = Form("")`, затем `classes.split(",")`.

Выход — список (или объект `{"detections": [...]}`, бэкенд понимает оба):

```json
[{"bbox": [0.41, 0.22, 0.12, 0.18], "cv_class": "pressure_gauge", "confidence": 0.87}]
```

- `bbox` — доли кадра `[x, y, ширина, высота]`, начало в левом верхнем углу;
- `cv_class` — строго из словаря `docs/component-types.md`;
- повторные рамки одного узла уже подавлены, порог уверенности уже применён.

Время ответа: бэкенд ждёт не больше `ai_detect_timeout_seconds` (3 с), затем отдаёт
телефону ошибку `503 ai_unavailable`, и приложение пропускает этот кадр. Цель — 3–5 ответов
в секунду.

## `POST /analyze` — анализ одного узла

Вход: `image` (вырезанный узел), `component_type` (`pressure_gauge`), `component_name`
(«Манометр на напорном патрубке МП-100»).

Выход:

```json
{
  "category": "check_recommended",
  "signs": ["следы коррозии на корпусе"],
  "explanation": "На корпусе видны рыжие пятна, похожие на коррозию",
  "recommendation": "Осмотреть корпус, оценить глубину коррозии",
  "assessment_confidence": 0.7,
  "image_quality": "ok"
}
```

- `category` — строго `no_visible_issues`, `check_recommended` или `possible_defect`.
  Любое другое значение бэкенд заменит на `check_recommended` с текстом
  «Автоматический анализ не выполнен» — «нет проблем» по ошибке не появится никогда;
- `image_quality` — `ok` или `poor`;
- тексты — на русском, одно-два предложения.

Время: бэкенд ждёт не больше `ai_timeout_seconds` (20 с), затем отдаёт телефону
ошибку `503 ai_unavailable`. Свой предел в 15 секунд (план Тимофея) должен
сработать раньше.

## `POST /identify` — оборудование по фото

Вход: `image`. Выход:

```json
{"recognized": true, "candidates": [{"equipment_id": "PU-001", "confidence": 0.82}]}
```

`equipment_id` — `PU-001` или `CC-001`. Названия добавит бэкенд. Порог `recognized`
бэкенд применяет и сам (`identify_threshold`).

## Проверка без телефона

Когда ИИ-сервис запущен, а в `backend/settings.json` стоит `"ai_mode": "real"`:

```
python backend/check_scenario.py --image demo/photos/<снимок>.jpg
```

Скрипт пройдёт весь сценарий через бэкенд и покажет, какой шаг не прошёл.

## Запуск на стенде — `ai/run.py`

ИИ-сервис на ПК Павла запускает `python stand.py` из корня репозитория — вместе с
бэкендом, одной командой (`docs/stand.md`). Для этого от ИИ-сервиса нужно:

| Что | Как |
|---|---|
| Точка входа | `python ai/run.py --port 8001` — запускается системным Python, сам ставит свои зависимости при первом запуске (как `backend/run.py`) |
| Адрес | слушает `127.0.0.1` — телефон к ИИ-сервису не обращается, только бэкенд на том же ПК |
| Готовность | `GET /health`: 503, пока модели грузятся, 200 — когда готов. Стенд ждёт до 10 минут |
| Вывод | журнал — в консоль (stdout/stderr); стенд пишет его в `logs/stand-ai.log` |
| Без клавиатуры | ничего не спрашивает (stdin закрыт); при ошибке — завершается с ненулевым кодом и понятным текстом |
| Без интернета | после первой установки не обращается в сеть: веса — с диска, автозагрузка и статистика библиотек отключены |
| Заглушка | `python ai/run.py --stub` — без моделей и видеокарты, ответы — примеры из этого файла |

Бэкенд при запуске через стенд сам переключается на настоящий ИИ (`ai_mode = "real"`),
править `backend/settings.json` не нужно.
