# Словарь типов узлов

`type` в базе бэкенда = `cv_class` в ИИ-сервисе. Имена классов — стабильные, не меняются
без согласия всех троих. Источник в коде: `backend/app/enums.py`.

## Распознаются ИИ (Тимофей)

| `type` / `cv_class` | Название на экране | Текст для детектора (ориентир, подбирает Тимофей) | Где встречается в демо |
|---|---|---|---|
| `electric_motor` | Электродвигатель | `electric motor` | PU-001: N-02; CC-001: C-11 (вентилятор) |
| `pressure_gauge` | Манометр | `pressure gauge` | PU-001: C-02 |
| `valve` | Запорная арматура | `valve` | PU-001: C-03, C-04 — **два однотипных узла** |
| `flange` | Фланцевое соединение | `pipe flange` | PU-001: C-05 |

Признаки дефектов (`signs` в `/analyze`): коррозия, течь/подтёки, механическое повреждение.

## Только в карточке, ИИ не ищет

| `type` | Название | Зачем |
|---|---|---|
| `pump` | Насос | узел-родитель в составе PU-001 (N-01) |
| `circuit_breaker` | Автоматический выключатель | состав CC-001 (C-12), случай «наступил срок замены» |

Бэкенд передаёт в `POST /detect` только распознаваемые типы из карточки
(поле `classes`). Если ИИ вернёт класс, которого нет в карточке, бэкенд пометит рамку
`not_in_card`.

## Однотипные узлы

Если в карточке несколько узлов одного типа, бэкенд различает их по полю `order`
(порядок слева направо на общем виде оборудования): у C-03 `order=1`, у C-04 `order=4`.
От ИИ нужны точные `bbox`, чтобы сортировка по `x` совпадала с этим порядком.
