# Словарь типов узлов

`type` в базе бэкенда = `cv_class` в ИИ-сервисе. Имена классов — стабильные, не меняются
без согласия всех троих. Источник в коде: `backend/app/enums.py`.

## Распознаются ИИ (Тимофей)

| `type` / `cv_class` | Название на экране | Текст для детектора (ориентир, подбирает Тимофей) | Где встречается в демо |
|---|---|---|---|
| `electric_motor` | Электродвигатель | `electric motor` | PU-001: N-02; PU-002: N-13 |
| `pressure_gauge` | Манометр | `pressure gauge` | PU-001: C-02 |
| `valve` | Запорная арматура | `gate valve`, `ball valve` | PU-001: C-03, C-04 — **два однотипных узла** |
| `flange` | Фланцевое соединение | `pipe flange`, `flanged joint` | PU-001: C-05; PU-002: C-16 |

Признаки дефектов (`signs` в `/analyze`): коррозия, течь/подтёки, механическое повреждение,
следы перегрева (только у `electric_motor`).

## Только в карточке, ИИ не ищет

| `type` | Название | Зачем |
|---|---|---|
| `pump` | Насос | PU-001: N-01 (Wilo, ТО-1 скоро); PU-002: N-11 (винтовой AMS) |
| `pipeline` | Трубопроводная обвязка | PU-001: N-03 — узел, к которому относятся задвижки, манометр, фланец |
| `mechanical_seal` | Торцевое уплотнение | PU-001: C-06 — 89 % ресурса; PU-002: C-13 |
| `bearing` | Подшипник | PU-001: C-07 — подшипники двигателя, «наступил срок замены» |
| `impeller` | Рабочее колесо | PU-001: C-08 — норматива нет («по состоянию»), сюда привязана вибрация 1x (дисбаланс) |
| `coupling` | Соединительная муфта | PU-001: C-09 — сюда привязана вибрация 2x (центровка) |
| `gearbox` | Редуктор | PU-002: N-12 — мотор-редуктор WXRF87 |
| `stator` | Статор винтовой пары | PU-002: C-11 — замена в истории, норматива нет |
| `rotor` | Ротор винтовой пары | PU-002: C-12 |
| `temperature_sensor` | Термопреобразователь | PU-002: C-14 — просрочена поверка |
| `relay` | Реле | PU-002: C-15 — реле тепловой защиты РТЗ-1М |

Бэкенд передаёт в `POST /detect` только распознаваемые типы из карточки
(поле `classes`). Если ИИ вернёт класс, которого нет в карточке, бэкенд пометит рамку
`not_in_card`.

## Однотипные узлы

Если в карточке несколько узлов одного типа, бэкенд различает их по полю `order`
(порядок слева направо на общем виде оборудования): у C-03 `order=1`, у C-04 `order=4`.
От ИИ нужны точные `bbox`, чтобы сортировка по `x` совпадала с этим порядком.

## Дефекты из материалов заказчика

Перечень `docs/case/Типы дефектов промышленного оборудования.docx` — видимые дефекты по
видам оборудования. Для наших распознаваемых типов и наших трёх видов признаков:

| Тип | Дефект из перечня | Наш признак (`signs`) |
|---|---|---|
| `electric_motor` | повреждение изоляции кабелей: трещины, оплавление, оголённые жилы | механическое повреждение |
| `electric_motor` | деформация рёбер охлаждения: погнуты, сломаны, отсутствуют | механическое повреждение |
| `electric_motor` | следы перегрева: краска корпуса бурая, жёлтая, радужная у щитов и клеммной коробки | следы перегрева — добавлен 13.11, только для `electric_motor` |
| `electric_motor` | отсутствие или обрыв провода заземления | **нет** — по снимку надёжно не определить, в признаки не добавляем |
| `valve` | протечка через сальник штока: капли, белый налёт солей, влажное пятно | течь/подтёки |
| `valve` | повреждение или отсутствие маховика, газовый ключ вместо маховика | механическое повреждение |
| `valve`, `flange` | коррозия фланцевых соединений: ржавые подтёки от болтов, вздутие краски | коррозия |
| `valve` | несоответствие индикатора положения штоку | **нет** — требует знания конструкции, не берём |
| `pipeline` (не распознаётся) | повреждение изоляции, трещины, коррозия — фото в `docs/case/Трубопровод` | коррозия, механическое повреждение |

Фото по этим дефектам — `docs/case/Насосные агрегаты`, `ЭД`, `Запорная арматура`,
`Трубопровод`. Снимков манометров в материалах нет — их Тимофей берёт из своего набора.
Часть фото — внутренние повреждения (подшипник, обмотки статора, рабочее колесо): по
ТЗ их не распознаём, но они хороши для ответа жюри, почему ИИ не диагностирует
внутренние неисправности.
