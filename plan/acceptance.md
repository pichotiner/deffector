По решению Тимофея этот документ определяет **оставшуюся работу и достаточную
приёмку**. Он имеет приоритет над прежними внутренними порогами, способами съёмки

организаторов и согласованный API остаются основанием требований.

Планы этапов сохраняют историю разработки. Пустой чекбокс сам по себе не означает
отсутствующую функцию: сначала учитываем `docs/coverage.md`, сообщения и новые записи.
Снятое условие обозначаем как снятое, а не как выполненный физический тест.

## 2. Что можно упростить

| Область | Достаточно для сдачи |
|---|---|
| Идентификация | Основной показ — QR и ручной выбор при неудаче. В ТЗ способы перечислены через «или»; маркировка, номер и фото не обязаны демонстрироваться в одном дубле. Непроверенную фотоидентификацию не обещаем как проверенную |
| ИИ | Несколько выбранных типов и признаков на проверенных объектах показа. Четыре типа остаются реализованным словарём, но не обещанием одинакового качества на всех кадрах |
| Эталоны и качество | Нет обязательного числа 5–10 снимков. Дополнительные телефонные эталоны нужны при проблеме фотоидентификации. Новые эксперименты, обучение и независимая IoU-разметка не являются условиями сдачи; точность заявляем только в пределах измеренного |
| Скорость и память | При звонке кадры обновляются, анализ завершается за приемлемое для показа время, ошибок памяти нет. 3–5 ответов/с и 12 ГБ — ориентиры разработки, не пороги приёмки. Числа измеряем, если приводим их в защите |
| AR | Читаемые метки поверх камеры, различимые статусы, причина/действие и переход к карточке. Пространственные якоря и новые 3D-объекты исходным ТЗ не требуются. Выбор кандидата инженером допустим вместо обещания порядка слева направо |
| Ресурс | Расчёт по доступным данным; отсутствующий норматив явно обозначен. Заполнять выдуманными нормативами все узлы не нужно |
| Доказательства | Для серверного расчёта подходит автотест/API, для отображения — телефон/запись, для физической работы — подтверждение участника. Не требуем нового видео для каждого пункта; не подменяем проверку интерфейса наличием кода |
| Повторы | Повторяем затронутую проверку после изменения кода/среды или нового сбоя. Не переустанавливаем готовый стенд и не перекачиваем прежние модели ради чекбокса |
| CI | Локальный успешный прогон на проверяемом коде допустим при блокировке Actions. Оплата GitHub не условие готовности прототипа |
| Видео | Одна читаемая запись сценария для подстраховки. Можно использовать уже снятый офлайн-сценарий; второй ракурс, отдельный proof, 30–40 секунд, строгие 3 минуты и сложный монтаж необязательны. Публикуем реальный файл/ссылку, исправляем ссылки и подписи под выбранный вариант |
| Сеть и звонок | Актуальный адрес ПК в настройках; закрепление IP желательно. Закрываем лишние программы, включая IDE. Один успешный проход показа в звонке, повтор — только после найденного сбоя |
