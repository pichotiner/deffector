## Что должно получиться

ИИ-сервис, который по запросу бэкенда выполняет три задачи. Защита проходит онлайн,
показывает Павел, поэтому **на защите сервис работает на ПК Павла** (RTX 5070 Ti,
16 ГБ видеопамяти) — ты разрабатываешь у себя, но ставится и запускается он там. Сервис:

1. находит узлы в кадре и возвращает их рамки (`/detect`);
2. оценивает видимые дефекты узла и объясняет результат (`/analyze`);
3. определяет образец оборудования по изображению (`/identify`).

Твой пункт ТЗ — 4.2 целиком, плюс идентификация по изображению из 4.1.

Организаторы разрешили предобученные модели и не оценивают веса — оценивается рабочая
технология. Поэтому берём готовые модели и не обучаем с нуля.

## Технологии

| Задача | Чем делаем |
|---|---|
| Сервис | Python, FastAPI, один процесс, модели загружаются при старте |
| Узлы и рамки | предобученный детектор с открытым словарём — OWLv2 (на этапе 0 сравнили с YOLOE и Grounding DINO, см. `ai/README.md`): классы задаются текстом, обучение не нужно |
| Дефекты и объяснение | локальная мультимодальная модель (класс Qwen-VL 7B) через Ollama |
| Идентификация по изображению | сравнение кадра с эталонными фото по векторным представлениям (CLIP ViT-B/32) |

**Сервис не должен требовать интернета** (ограничение организаторов, раздел 4.1 README).
Облачные ИИ-сервисы не используем совсем. Все веса скачиваются заранее и лежат на диске;
сервис загружает их по локальному пути. Автоматическую загрузку моделей и отправку
статистики в библиотеках отключи — иначе без сети сервис может зависнуть при старте.

**Запас по видеопамяти.** Детектор и мультимодальная модель вместе занимают не больше
12 ГБ. На ПК Павла во время защиты открыты ещё видеозвонок и трансляция экрана телефона,
а 12 ГБ — это ровно твоя видеокарта.

**Твой ПК.** RTX 5070 с 12 ГБ видеопамяти и Windows — та же система, что на стенде
у Павла. Обе модели разрабатываешь и проверяешь прямо у себя: что помещается и работает
у тебя, поместится и у Павла. Пробная установка у Павла всё равно обязательна.

**Установка на чужой ПК** (раздел 4.2 README). Сервис ставится и запускается на ПК Павла
одной командой из репозитория, без твоего участия. Стенд у Павла работает
в Windows. Скрипты установки и запуска пиши на Python, чтобы они одинаково работали
у тебя и у него; всё, что зависит от системы (пути, установка Ollama, расположение
весов), опиши в `ai/README.md` для Windows.

Названия — ориентир. Точные модели и версии выбираешь на этапе 0 сравнением на наших фото;
перед установкой сверь актуальные версии по документации.

### Этап 2. Дефекты, объяснения, идентификация — до 12:00, 14.11

- [x] **`POST /analyze` (4.2, дефекты и классификация):**
  - вход: `image` (вырезанный узел), `component_type`, `component_name`;
  - выход:

    ```json
    {
      "category": "check_recommended",
      "signs": ["следы коррозии на корпусе"],
      "explanation": "На корпусе видны рыжие пятна, похожие на коррозию",
      "recommendation": "Осмотреть корпус, оценить глубину коррозии",
      "assessment_confidence": 0.7,
      "image_quality": "ok"
    }
    ```

  - `category` — строго одно из трёх: `no_visible_issues`, `check_recommended`, `possible_defect`;
  - `signs` — только из утверждённого списка: коррозия, течь/подтёки, механическое повреждение,
    следы перегрева (только у электродвигателя);
  - `explanation` — одно-два предложения: что именно видно на изображении;
  - `recommendation` — что проверить дальше;
  - тексты на русском.
- [x] **Правила классификации** (зашить в инструкцию модели и проверить кодом):
  - явные признаки дефекта → `possible_defect`;
  - сомнительные признаки → `check_recommended`;
  - плохой снимок (смазан, тёмный, узел закрыт или слишком мелкий) → `image_quality: "poor"`
    и **всегда** `check_recommended` с объяснением «по снимку оценить нельзя» —
    никогда `no_visible_issues`;
  - `no_visible_issues` — только при хорошем снимке без признаков.
- [x] **Ограничения формулировок** (требование ТЗ):
  - модель описывает только то, что видно на изображении;
  - не утверждает наличие внутренней неисправности и не ставит диагноз;
  - не пишет «исправен», «в порядке», «дефектов нет» — только «видимых проблем не обнаружено».

  После ответа модели — проверка кодом: если в тексте есть запрещённые слова, ответ
  заменяется шаблонным для данной категории.
- [x] **Надёжность ответа:** модель отвечает в формате JSON по схеме; ответ проверяется;
      при сбое формата — один повтор; при втором сбое или превышении 15 секунд —
      `check_recommended` с объяснением «автоматический анализ не выполнен». Нулевая
      случайность генерации, чтобы на одном и том же снимке ответ не менялся.
- [x] **Уверенность (4.2):** `confidence` в `/detect` — уверенность детектора в распознавании
      узла, возвращается всегда. `assessment_confidence` в `/analyze` — оценка самой модели;
      в документации честно указать, что это не калиброванная вероятность.
- [ ] **Сопоставление с карточкой (4.2)** — делаете вместе с Андреем, код на стороне бэкенда:
  - `cv_class` совпадает с `type` узла в карточке;
  - если в карточке несколько узлов одного типа — различаются по порядку слева направо
    (в карточке у узла есть поле порядка); если различить нельзя — `ambiguous`;
  - распознанный узел, которого нет в карточке, — `not_in_card`.

  Твоя часть: стабильные имена классов и проверка на фото, что порядок слева направо работает.

## Чек-лист приёмки (формулировки ТЗ, раздел 4.2)

- [ ] Распознаются выбранные типы узлов и комплектующих.
- [ ] Выявляются доступные для визуального обнаружения дефекты и отклонения.
- [ ] Результат классифицируется по трём категориям: «видимых проблем не обнаружено»,
      «рекомендуется проверка», «обнаружены признаки возможного дефекта».
- [ ] Обнаруженные компоненты сопоставляются с данными цифровой карточки.
- [ ] Формируется краткое объяснение причины предупреждения и рекомендация по дальнейшей проверке.
- [ ] Отображается степень уверенности модели в результате распознавания.
- [ ] Анализ подан как инструмент предварительного осмотра.
- [ ] Система не подтверждает внутреннюю неисправность, которую нельзя установить по изображению.
- [ ] Отсутствие видимых дефектов не трактуется как подтверждение исправности.
- [ ] Оборудование идентифицируется по изображению (4.1).
- [ ] Сервис запускается и отвечает на все три запроса без подключения к интернету.
