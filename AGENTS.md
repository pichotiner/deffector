# Инструкции для ИИ-агентов

Проект: прототип мобильного AR-помощника инженера для хакатона «Кибер 102»
(задача КСТ Энерго Инжиниринг). Команда — три человека, у каждого своя роль и своя папка.
Отвечай и пиши документацию на русском.

## В начале каждой сессии — обязательно

1. **Спроси разработчика, кто он**, если он сам не назвался в первом сообщении:
   Андрей, Павел или Тимофей. Не угадывай по имени в git, почте или путям — спроси.
   От ответа зависит, какой план читать и какие сообщения показывать.

   | Кто | Роль | План | Папки |
   |---|---|---|---|
   | Андрей | бэкенд, данные, цифровой двойник; презентация | [plan/andrey-backend.md](plan/andrey-backend.md) | `backend/`, `docs/`, `demo/print/` |
   | Павел | Android-приложение и AR; стенд и показ на его ПК и телефоне | [plan/pavel-mobile-ar.md](plan/pavel-mobile-ar.md) | `mobile/` |
   | Тимофей | ИИ и компьютерное зрение; тимлид | [plan/timofey-ai.md](plan/timofey-ai.md) | `ai/`, `demo/photos/`, `demo/reference/` |

2. **Прочитай [TEAM_MESSAGES.md](TEAM_MESSAGES.md)** — это делается всегда, без напоминаний.
   В нём обращения людей друг к другу; задачи роли — в её плане (шаг 3), их не путай
   и в сообщения не копируй.
   Покажи разработчику:
   - **все невыполненные обращения к нему** (`- [ ] Имя: …`) — со сроками, самые срочные первыми;
   - новые сообщения ему или всем за последние сутки — коротко.
   Предложи начать с невыполненных обращений, если они важнее текущей задачи.
3. Прочитай [plan/README.md](plan/README.md) (общий план, контракт API, график) и план
   его роли. Текст задания — [docs/tz/TZ.md](docs/tz/TZ.md).

## Правила работы (из плана, раздел 1)

- Делаем всё, что в ТЗ, и строго как в ТЗ. Подписи статусов и категорий — дословно из ТЗ.
- Дополнительные функции не делаем. Идея сверх ТЗ — в [plan/future.md](plan/future.md).
- **Готовый прототип работает без интернета.** Никаких облачных сервисов, загрузок
  моделей, шрифтов и библиотек во время работы, аналитики, отчётов о сбоях.
- Контракт API (раздел 5 плана, `backend/app/schemas.py`, `backend/openapi.json`,
  `docs/ai-contract.md`) меняется только по согласию всех троих — через сообщение
  в `TEAM_MESSAGES.md`.
- Стенд для показа — Windows на ПК Павла. Скрипты установки и запуска — на Python,
  пути — средствами Python, без `.bat` и `.sh`.
- Работаем в своей папке. Нужна правка в чужой — сначала сообщение её владельцу.
- Рабочие изменения часто вливаем в `main`: Павел запускает стенд из `main`.
- После 14.11, 18:00 (МСК) новых функций нет — только исправление ошибок.

## TEAM_MESSAGES.md — вести активно

**Отмечай выполненное.** Как только в сессии сделано то, о чём просили разработчика
(`- [ ] Имя: …`), отметь пункт: `- [x] Имя: … — сделано 13.11, 15:10`. Если по пункту
есть результат, который ждут другие (адрес сервиса, ответ на вопрос), допиши его под пунктом
с отступом. В старых сообщениях меняй только отметки и ответы под пунктами — текст не трогай.

**Добавляй сообщения** сверху (формат — в начале файла), если в этой сессии:

- изменился контракт API, формат данных, словарь типов узлов, демо-данные;
- изменились команды установки, запуска, сброса, проверки;
- готово что-то, чего ждут другие (заглушка, сервис, сборка APK, файлы для печати);
- нужно что-то от другого участника или есть вопрос к нему;
- принято решение, затрагивающее всех.

Каждую просьбу к человеку оформляй отдельным пунктом `- [ ] Имя: что сделать — срок`.
Подпись — от имени разработчика, с которым работаешь (`Андрей → Павлу`). Время — МСК.
Покажи текст разработчику перед коммитом и закоммить файл вместе с работой — сообщение
должно попасть в `main` вместе с изменением, о котором оно говорит.

**Перед концом сессии** проверь: всё ли сделанное отмечено, обо всём ли, что затрагивает
других, написано.

## Команды

```
python stand.py                    # стенд: ИИ-сервис + бэкенд одной командой (docs/stand.md)
python backend/run.py              # бэкенд: установка при первом запуске и запуск
python backend/reset_db.py         # сброс базы к демо-данным
python backend/check_scenario.py   # проверка всех 10 шагов сценария через бэкенд
cd backend && python -m pytest     # тесты бэкенда (нужен requirements-dev.txt)
cd backend && python -m app.export_openapi   # обновить openapi.json после правки schemas.py
python docs/presentation/make_pdf.py          # slides.html → slides.pdf (Edge или Chrome)
python docs/video/make_video.py docs/video/scenario.json   # монтаж видео по списку вырезок (нужен ffmpeg)
```

Команды ИИ-сервиса и приложения — в `ai/README.md` и `mobile/README.md`, когда появятся.
